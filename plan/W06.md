## 2. 职责边界（最容易越界的一处）

| 谁 | 负责 | 不负责 |
|---|---|---|
| **本窗口（执行面）** | 把"一个任务"变成"一个运行中的会话"；Worker 怎么领活、怎么交货；Orca 的六个原子动作 | 任务该派给谁（W03）、预算够不够（W07）、PR 合不合规（W09） |
| W03（调度面） | 队列、租约、能力匹配 | 会话内部怎么跑 |
| Orca 本身 | worktree 隔离、跑编码 Agent、PTY、snapshot | Issue 状态管理 |

**关键原则：接口做浅、语义做深。** 只依赖 Orca 的四个稳定事实：CLI 存在、worktree、PTY、hooks。
它的 UI、数据库、内部配置**一概不碰**——`INTEGRATION-ORCA.md` 已明确它没有公开 HTTP API/SDK。

## 5. 红线

- **不在请求处理器里跑长任务**：spawn 立刻返回，过程写事件表。
- **不直接改 `tasks` 表**：一切通过 `tasks.service` 的公开函数，保证状态机是唯一入口。
- **不做"过程干预"**：L3 类 Agent 只做生命周期管理，不试图 inside-the-loop 指挥它怎么想。
