## 2. 为什么这个窗口排第一

其它 9 个窗口都要用三样东西：**认证依赖**、**错误结构**、**日志里的 request_id**。
这三样在骨架里已经能跑，但「刷新令牌轮换 + 吊销」和「RBAC 判定」没有，
后面每个窗口都会自己写一遍，最后就会出现三套鉴权逻辑。所以本窗口的第 1 个 issue 必须最先合并。

## 3. Issue 清单与执行顺序

**严格串行**：一次只做 1 个 issue，做完即 commit + push + 更新 Draft PR，再开下一个。
顺序为「契约 → 实现 → 加固」，不允许跳过 I01 直接做 I03。
