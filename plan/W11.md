## 2. 为什么需要这个窗口

四份上游文档里，`INPUT-CHANNELS-v1.md` 是唯一**一个 issue 都没排**的：
它对 v0.2 提了 6 处修订、定义了 4 条输入通道和 4 种产出物，但 W01–W10 的
60 个 issue 里没有任何一个落地它。缺口对照：

| 文档已设计 | 现有排期 | 缺口后果 |
|---|---|---|
| 四道闸分流 + 排队区（日 ≤12 条进 Inbox） | 无（W02 只有 14 天归档） | 多通道一开，Inbox 三天爆仓，然后你不再打开它 |
| 缺席窗口 + 回归简报（通道 D） | 无 | 「回来 5 分钟看到结果」完全不存在，无人值守不可用 |
| 截图→工具评估管线（通道 B） | 无 | 截图变收藏夹，永远不看 |
| 金融静默 + 判断校准簿（通道 C） | 无 | 认知进化轨缺唯一可量化的产出物（准确率曲线） |
| 信息源绩效卡与自动降权 | 无 | 营销号噪声无法自动沉降，只能手动退订 |
| 统一通知（每日 ≤3 条、21:00 汇总） | 无（drift / dropped / queued_overdue / breaker 各自落库） | 告警无处可达，等于没有告警 |
| 采集入口（快捷指令 / 微信自聊 → Inbox） | 无（只有 REST API） | 「30 秒接住体感」不成立，P0 毕业标准难达成 |

启动条件：**P2 毕业（3 目标并行、日决策 ≤12）之后**；或 Marshal 批准提前。

## 3. 三条产品红线（来自 INPUT-CHANNELS，实现时不能「优化」掉）

1. **默认不打扰**。采集器的默认动作是静默归档，不是入库；过不了闸的输入永不进收件箱。
2. **回归简报最多 3 条决策**，每条 20 秒能读完；必须有「全部知道了」一键归档。
   多于 3 条说明系统没做压缩，把它的工作扔回给了你。
3. **无人值守绝不放行高风险动作**。缺席窗口内 L0/L1 一律冻结待审；
   第一次无人值守烧钱或发错内容，这个功能就永远不会再被启用。
