## 2. 核心判断：GitHub 是 oracle，不要让模型自评

```
PR checks 通过 + PR merged  → task verdict = ok      → 计入 CPO
PR closed 未合并            → verdict = rework
CI 失败 3 次                → 熔断，转人工
```

**不要双向同步 Issue 状态。** 真相源只有两处：任务与预算在 Postgres，验收信号在 GitHub。
同步做多了会打成两套互相覆盖的状态，这是最常见的坑。

### W09-I01 · Webhook 接收与验签
| 项 | 内容 |
|---|---|
| 状态 | TODO |
| PR | — |
| Wave | 1 |
| commit | `feat(#<issue>): webhook-verify` |
| 产出 | `POST /github/webhook`、`modules/github_sync/{router,service,verify}.py` |
| 关键文件 | `github_events` 表、`migrations/versions/w09_01_github.py` |
| 验收 | ① 校验 `X-Hub-Signature-256`（HMAC-SHA256，密钥 `GITHUB_WEBHOOK_SECRET`）；② 时间戳/重放防护：`X-GitHub-Delivery` 唯一索引，重复投递返回 200；③ 原始 payload 落库（`github_events.payload` JSONB），**先落库再处理**，处理失败可重放；④ 5 秒内返回 200（GitHub 超时会重投），重活进后台；⑤ 单测：签名错误、重放、超大 payload |
