## 2. 这个窗口最容易出错的地方（先读再动手）

1. **队列必须是 Postgres，不是 Redis**。`SELECT ... FOR UPDATE SKIP LOCKED` 就是队列。
   Redis 只做限流；用 Redis 当队列会和 PG 形成两套真相（架构文档 §2.1 已明确）。
2. **租约时间必须显著大于心跳间隔**。心跳 30 s、租约 90 s，即容忍丢 2 次心跳。
   如果租约 ≤ 心跳间隔，正常任务会被误回收，表现为"任务反复重启"。
3. **回收次数是有限资源**。连续 3 次回收进死信（`tasks.state = 'dead'`），
   **绝不静默丢弃**——这是产品红线之一。
4. **能力标签不匹配就不派**。`requires.always_on = true` 的任务绝不派给笔记本，
   这是"任务莫名卡住"的头号原因。
