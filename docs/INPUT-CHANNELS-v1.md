# 信息通道设计 v1

**日期**：2026-10-18
**关联**：`PRODUCT-DESIGN-v0.2.md`
**一句话结论**：你给的四个例子不是四个功能，是**四种注意力状态**。同一套分流机制，四种不同的处理契约；搞混了就会做出四个互不相干、都很烦人的采集器。

---

## 0. 先看穿这四个例子

| 你说的 | 表面是 | 本质是 |
|---|---|---|
| 有空 2 倍速看视频，感受声音细节；没空让 AI 汇总 | 视频摘要功能 | **同一内容，两种消费模式**——一个要保留体验，一个要只要判断 |
| 小红书截图里的工具，要提取 GitHub 链接再评估 | 截图 OCR | **碎片 → 工单的管线**——终点不是收藏，是"要不要纳入工作流" |
| 每天看资产走势、研究金融新闻 | 行情监控 | **默认安静的监测流**——怕的不是漏，是被吵 |
| 运动 3 小时脱离 AI，回来要结果 | 定时任务 | **缺席契约**——价值不在跑了多少，在回来那 5 分钟看到什么 |

**共同点**：都不是"把信息抓进来给你看"，而是"**替你做掉判断，只在必要时打断你**"。

**这直接决定了设计原则**：

> 采集器的默认动作是**不打扰**，不是入库。所有输入先过四道闸，过不了线的直接静默归档，**永不进收件箱**。

理由很实际：如果四个通道都往 Inbox 灌，Inbox 三天就爆，然后你就不打开了——这正是所有"稍后读"类工具的死法。

---

## 1. 核心抽象：注意力模式是一等公民

产品的第一个对象不是"信息源"，是"**你现在处于哪种注意力状态**"。同一个视频，状态不同，处理方式必须不同。

| 模式 | 触发 | 你的状态 | 系统该做什么 | 绝对不该做什么 |
|---|---|---|---|---|
| **沉浸** | 主动选择"我要好好看" | 有时间、要体验 | 生成**伴随物**：章节时间轴、术语卡、可回看标记点 | 边看边弹摘要（破坏体验） |
| **掠过** | 没时间 / 排队中 | 碎片时间 | 生成**决策摘要**：值不值得深看 + 看哪一段 | 生成"知识总结"（你不看，无用） |
| **拾取** | 截图 / 随手保存 | 3 秒 | 结构化成**评估工单**，进入待处理队列 | 只存书签（永远不看） |
| **缺席** | 运动 / 睡眠 / 会议 | 不在 | 自治运行 + **回归简报** | 堆日志（回来面对一堵墙） |

这四种模式解决的是同一个问题的四个侧面：**信息进来了，但你的处理能力有限**。所以每种模式都必须定义"给你的最小必要物"。

## 2. 统一分流：四道闸，默认不进收件箱

```
输入（4 通道）
   ↓
闸 1 价值：和现有目标/资产相关吗？来源可信吗？
   ↓ 不过 → 静默归档（记录，不打扰）
闸 2 时效：过期就没用了？
   ↓ 过期的 → 归入"历史"，不进队列
闸 3 注意力：现在是什么模式？能给我多少时间？
   ↓ 不匹配 → 排队到下一次对应窗口
闸 4 预算：今天的内容预算 / 钱预算 / 带宽还剩多少？
   ↓ 超了 → 顺延（并告诉你顺延了几条）
   ↓
三种产出之一：Brief（判断） / Card（认知） / Journal（记录）
```

**闸 1 的四项打分**（权重可调，初始值是我拍的，需校准）：

| 维度 | 判什么 | 权重 | 备注 |
|---|---|---|---|
| 目标相关性 | 与在跑目标/观察清单的语义距离 | 35% | 最硬的一项 |
| 来源可信度 | 该来源历史"推荐后我真的用了"的比例 | 25% | 见第 8 节信息源绩效卡 |
| 新颖性 | 是否已知/重复（向量去重 + URL 归一化） | 20% | 防同一个工具被推 5 次 |
| 行动性 | 是否会导致一个具体动作 | 20% | 纯知识型内容天然低分，这是刻意的 |

**过线后仍要限量**：每天最多 12 条进"Inbox 待处理"。超过的按分数排队，页面显示"另有 37 条在排队"——**看得见的积压比看不见的积压安全**，因为它不会制造"我全都错过了"的焦虑。

## 3. 通道 A：长视频（订阅频道）

### 3.1 双模消费

| | 沉浸模式 | 掠过模式 |
|---|---|---|
| 触发 | 你点"我要看" | 你点了"给我摘要" / 排队超 3 天自动转 |
| 前置动作 | 生成章节时间轴（按语音转写的段落切分） | — |
| 伴随物 | 侧边术语卡、时间戳标记（你按一下记一个点，回来可跳回） | — |
| 产出 | **认知卡**（1 张，触发条件/规则/反例/置信度） | **决策摘要**（见下） |
| 成本 | ≈¥0.1（转写 + 章节） | ≈¥0.05 |
| 验收 | 有卡才算"看过" | 有"去/不去"的结论才算"掠过" |

### 3.2 决策摘要的结构（关键：输出是判断，不是知识）

普通摘要的问题是"信息仍然很多，只是短了一点"。你要的不是短版本，是**一个决定**：

```yaml
一句话: 这期讲"为什么复杂系统会突然崩"，核心是冗余与耦合的权衡
我的相关性: 高 —— 与你 O-E-011（复杂系统阅读目标）直接相关
建议: 值得深看，重点 12:40–18:20（讲"正常事故"那段，其他是铺垫）
关键论点: 3 条（每条 ≤20 字）
提到的实体: 工具/书/人（自动进"拾取"通道评估）
反向观点: 他反对的是什么（用来找反例，喂给认知卡）
```

**为什么必须有"建议"这一行**：摘要的唯一价值是帮你决定"要不要花 40 分钟"。没有这个决定的摘要，只是把消费从视频转移到了文字，总量没减。

### 3.3 频道治理

- 订阅源按"**你实际深看的比例**"排序，不按更新频率。一个更新很勤但你从不看的频道，应该被降权到"周报合集"里，而不是每天占你三条。
- 每个频道有配额（每周 ≤N 条进队列）。这一条能立刻砍掉 70% 的信息量。
- 支持"批量掠过"：一次给 10 条视频出 10 个一行决策，你花 2 分钟扫完。

## 4. 通道 B：截图 → 工具评估（五段管线）

这是四个通道里**最像工程管线**的一个，也是最容易做成"又一个收藏夹"的一个。区别在于终点定义。

### 4.1 五段

| 段 | 做什么 | 失败处理 |
|---|---|---|
| 1 入库 | 手机相册监听 / 分享到微信自聊 / 手动拖入 | — |
| 2 抽取 | OCR + 实体识别：GitHub URL、仓库名、工具名、作者、截图里的评价文字、小红书账号水印 | OCR 不确定 → 标"待确认"，不猜 |
| 3 补全 | 短链/截断链接 → 用仓库名搜索补全；抓 repo 元数据（star、最近 commit、license、语言、依赖） | 补不全 → 生成一个"手动确认"卡片，30 秒解决 |
| 4 **评估** | 自动生成评估卡（见 4.2） | 网络失败 → 重试 2 次后进死信 |
| 5 收纳 | 结论三分：**纳入工作流 / 观察 / 丢弃**。纳入 → 自动生成 harness 模板草稿 | — |

**核心设计**：截图不是收藏，是**工单入口**。默认产出是"评估卡"，不是书签。你说"后续我需要去分析、下载安装、是否加入工作流"——那这三步应该被系统接走，而不是留给你记着。

### 4.2 工具评估卡（可复用为"工具雷达"）

| 字段 | 怎么来 | 为什么重要 |
|---|---|---|
| 是什么（一句话） | 读 README 首段 | 判断是否与已有工具重叠 |
| 活跃度 | 最近 commit、issue 平均响应、release 频率 | 停更的工具是负资产 |
| 许可与成本 | license、是否需要付费 API、是否要自托管 | 决定能不能进工作流 |
| **安全风险** | 是否需要 token/密钥、是否上传数据、是否有网络外联、是否要 root | **红线项**：不明 repo 一律先在容器里跑，不在主机跑 |
| 与我现有工具的重叠度 | 与工具库比对功能向量 | 避免"第 7 个笔记工具" |
| 试用记录 | 沙盒跑一次，记录成功/失败原因 | 这是"评估"与"看 README"的区别 |
| 结论 + 理由 | 三选一 | 没有结论的评估等于没做 |

### 4.3 来源也要算账

截图里通常有原发布者。记录 `来源账号 → 推荐过的工具数 → 我最终采纳数`，算出**采纳率**。采纳率低于 20% 的账号，其推荐自动降权到"月度合集"。

营销号推荐的低质工具是这个通道最大的噪声源，而**唯一可靠的过滤器是历史采纳率**，不是人工判断。

## 5. 通道 C：金融资产与新闻（静默监测）

### 5.1 与内容通道相反的设计

内容通道怕漏（漏掉一个好工具/一期好内容，有损失）；金融通道**怕吵**（大部分时候没有信息量，打扰就是负价值）。

| | 内容通道 | 金融通道 |
|---|---|---|
| 默认状态 | 待分流 | **静默**（不打扰是常态） |
| 推送逻辑 | 有东西就推（限量） | **只有异动才推** |
| 失败模式 | 错过 | 噪声疲劳 → 你开始无视所有提醒 |

### 5.2 三层结构

```
① 观察清单（watchlist）
   资产 + 关注理由 + 阈值（涨跌幅 / 波动率 / 成交量异常 / 相关性破裂）
        ↓ 每 15–60 min 扫描，正常时完全静默
② 异动事件卡（只在触发时生成）
   发生了什么 / 可能原因（匹配同期新闻）/ 对我意味着什么 / 建议动作
        ↓
③ 判断校准簿（Prediction Journal）——这是本通道最被低估的部分
   你每次做判断时，记一句 + 预期 + 时间点
   T+7 / T+30 自动回看：对了吗？错在哪？
```

### 5.3 判断校准簿（为什么它比行情重要）

你说"每天花时间观察走势、研究新闻"。这件事的真实价值不是"抓住机会"，而是**训练判断力**。而判断力无法通过"看更多"提升，只能通过"记录 → 回看 → 修正"提升。

产品上就一件事：**让你每次判断留一行**，然后系统在 T+7/T+30 把它翻出来对账。

不需要复杂——一个输入框 + 自动对账 + 月度准确率。但这一个功能的价值，高于任何花哨的行情看板。它也是"认知进化"轨里唯一**可量化**的产出物（准确率曲线）。

### 5.4 红线

- 系统**不做**投资建议，不预测点位，不给"买入/卖出"结论，只做信息组织与判断记录。
- **不做自动交易**，任何下单动作 100% 人工，且不进任何自动化流程。
- 事件卡的措辞必须是"可能原因"，不是"原因是"——因果归因在金融里极易错，措辞会塑造你的判断习惯。

## 6. 通道 D：缺席窗口（运动 3 小时）

这是四个通道里最有意思的一个，因为它定义的不是"输入"，而是"**一种时间契约**"。

### 6.1 三段结构

```
[ 离开前 60 秒 ] 交接
   "这 3 小时我打算做这 4 件事，预计 ¥12。要调整吗？"
   → 一键确认 / 改预算 / 只做第 1 项 / 改成只读模式
        ↓
[ 3 小时 ] 自治运行
   允许：读、抓、分析、草拟、内部整理、批量生成、备份、模型测评
   禁止：发布、花钱（超预算）、删除、对外沟通、改配置
        ↓
[ 回来 5 分钟 ] 回归简报（Return Brief）
```

**为什么要有"离开前 60 秒"**：自治的信任不是靠"我相信它"，是靠"我在离开前知道它要干什么"。这 60 秒是整套机制的**成本最低、收益最高**的部分——没有它，你回来第一件事是审计，而不是决策。

### 6.2 回归简报的结构（本通道的核心产出物）

```
┌─ 一句话 ─────────────────────────────────────┐
│ 你不在的 3 小时：1 件需要你定，12 件已处理完  │
│ 成本 ¥9.4 / 配额 12%                          │
└──────────────────────────────────────────────┘

① 需要你决策（最多 3 条，每条 20 秒能读完）
   [选项 A / B] + 推荐 + 不做的后果

② 已完成（折叠成一行，可展开）
   12 项完成 · 3 个目标推进 · 2 条内容待发（已排队等闸门）

③ 异常（有才显示，没有就完全不出现）
   14:20 起了 1 次熔断（Provider X 超时），已切备用

[ 全部知道了 ]  ← 一键归档，不用逐条点
```

**三条设计纪律**：
1. **最多 3 条决策**。多于 3 条说明系统没做压缩，把它的工作扔回给你了。
2. **异常不藏**。宁可难看，不能"看起来一切正常"，否则你下次就不敢离开了。
3. **必须有"全部知道了"这个按钮**。逐条确认是设计失败——它把你的 5 分钟变成 20 分钟。

### 6.3 无人值守降级（必须做，否则不敢用）

3 小时里出问题是必然的。关键是**它自己知道停**：

| 触发 | 动作 |
|---|---|
| 预算耗尽 | 停派活，只保留只读；简报顶部标红"14:20 因预算停摆" |
| 连续 3 个同能力任务失败 | 熔断该能力，切备用 Provider；仍失败 → 停止该目标分支 |
| 出现高风险动作请求 | 冻结在待审队列，等回来批，**绝不自动放行** |
| 全局异常（账号/密钥/网络） | 进入安全模式：只读 + 备份，简报置顶告警 |

**这一条比"能跑多少任务"重要。** 第一次无人值守出事如果烧掉一笔钱或发错一条内容，这个功能就再也不会被启用了。

### 6.4 顺带一个收益：把重活排进离线窗口

运动 3 小时是**每天最稳定的离线块**。它应该被当作"批处理时段"来用：

- 批量抓取、批量生成、全量扫描、模型雷达测评、夜间备份、大文件处理、跨库去重
- 这些任务**不需要人介入**，正好填满这个窗口
- 效果是：你回来时，昨天攒的"重活"已经做完了

这比"定时任务 02:00 跑"更贴近你的真实作息——你的机器不需要在凌晨干活，需要在你不在的时候干活。

## 7. 反推荐：时间盒与内容预算

四个通道都会面临同一个诱惑：**给你更多**。这是推荐算法的默认方向，也是这个产品必须反着来的地方。

| 机制 | 做法 |
|---|---|
| 内容预算 | 每天 60 min（可调）。超了不再出新的，只显示"还有 N 条在排队" |
| 播单式消费 | 每天生成 3–5 条"今日待看"，而不是无限流 |
| 建议时长 | 每条带 `3 min / 15 min / 45 min` 标签，你按当下时间挑 |
| 看完即停 | 预算用完，页面主动变成"今天到此为止"，不再有下一个 |
| **KPI 反向** | 不考核"消费了多少"，考核**每 30 分钟产出的可行动条目数** |

最后一条是关键：如果"看了 5 个视频、产出 0 个行动"，这个指标会告诉你——**你在消费，不是在推进**。这正是内容型产品的成瘾机制，必须用指标对抗。

## 8. 横切机制：信息源绩效卡

Agent 有绩效卡（谁在拖后腿）。**信息源也该有**——而且是同一套逻辑。

| 来源 | 记录 | 用途 |
|---|---|---|
| YouTube 频道 | 推送数 → 深看率 → 认知卡数 | 降权从不看的频道 |
| 小红书账号 | 推荐工具数 → 采纳数 | 过滤营销号 |
| 新闻源 | 触发事件数 → 事后被验证的比例 | 过滤标题党 |
| 金融信息源 | 引用次数 → 判断准确率贡献 | 只留真正有用的 |

**注意口径**：这不是给"人"打分做考核，是给**信息通道**算噪声比。降权的唯一后果是"少打扰你"，不是"否定谁"。

这一层价值很高，因为它能自动完成"信息源清洗"——你不用手动退订，系统自己把噪声沉下去。

---

## 9. 四种产出物（统一命名，避免概念增殖）

全系统只有四种产出，所有通道都归到这四种，不再新增：

| 产出物 | 是什么 | 谁产生 | 验收 |
|---|---|---|---|
| **Brief 简报** | 一个判断（去/不去、要不要深看、值不值得做） | 掠过模式、周报 | 有明确结论 |
| **Card 卡片** | 一条可复用规则（触发条件/规则/反例/置信度/失效期） | 沉浸模式、复盘 | 能被另一个目标引用一次 |
| **Journal 台账** | 一条可对账的记录（判断 + 预期 + 时间点） | 金融观察、决策 | T+N 完成对账 |
| **Eval 评估** | 一个工具/能力的结论（纳入/观察/丢弃） | 截图通道 | 有结论 + 理由 |

四种产物的共同点：**都必须在某个时点被"用一次"才算完成**。没被用过的卡片和没被对过账的判断，都是库存，不是资产。

## 10. 与目标体系的关系

输入不直接变成目标，中间要过一次"**这值不值得占用带宽**"：

```
输入 → 四种产出 → 三条去向
                    ├→ 喂给现有目标（80%）     ← 大多数输入的正确归宿
                    ├→ 提议新目标（15%）        ← 需要过闸 + 你上午拍板
                    └→ 直接归档（5%）           ← 有用但无行动性，备查
```

**关键比例**：**80% 的输入应该被现有目标吸收**，只有 15% 能提议新目标。如果这个比例反了（大量输入在催你立新目标），说明目标定得太窄，或者你在用"收集"代替"推进"。

---

## 11. 落地顺序（不要四个一起做）

| 顺序 | 做哪个 | 工期 | 理由 |
|---|---|---|---|
| **1** | 通道 D 缺席窗口（回归简报） | 1 周 | 它复用最少的依赖（只要有个任务表 + 简报生成），但**体验冲击最大**——第一次用就会觉得"这个系统值了" |
| **2** | 通道 B 截图管线 | 1.5 周 | 有明确终点（评估卡），能验证"输入→工单→结论"是否成立 |
| **3** | 通道 C 金融静默 + 判断簿 | 1 周 | 静默机制是带宽设计的最佳试验田；判断簿是认知进化的唯一量化产出 |
| **4** | 通道 A 视频双模 | 1.5 周 | 依赖最重（转写、章节、成本），且最容易做成"又一个播客工具" |

**为什么 D 排第一**：它是唯一一个"用户离开 3 小时、回来被惊艳"的功能，而其他三个都需要长期使用才见效。**先做一个让人相信的产品，再做一个正确的产品。**

## 13. 风险

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 无人值守时越权（发布/花钱/删除） | 中 | **极高** | 缺席契约白名单；高风险一律冻结待审；**绝不放行** |
| 装错工具（OCR 把 `foo` 认成 `f00`） | 中 | 高 | 补全阶段必须双源校验；装之前容器沙盒跑；来源不明直接拒绝 |
| 金融信息被当成建议 | 中 | 高 | 措辞规范（"可能原因"）；不做预测点位；不接自动交易 |
| 摘要替代思考（看了摘要就不看原文） | **高** | 中 | 摘要只给"要不要看"的决定，不给"知识总结"；关键论点最多 3 条 |
| 信息源绩效卡被误当考核 | 低 | 中 | 明确口径：只影响推送权重，不影响任何人的评价 |
| 四个通道同时上线导致 Inbox 爆 | 高 | 中 | 严格按第 11 节顺序，一次只开一个通道 |

---

> **一句话收尾**：这四个例子的共同点不是"信息来源多"，而是"**你不可能都处理**"。所以设计的重心不在采集，在**分流与压缩**——四道闸决定什么进来，四种产出决定留下什么，缺席契约决定你不在时它能走多远。
